# Q1.3 数据清洗策略

## 一、针对不同下游用途制定清洗方案

**用途 A：销售总额统计与报表**

区分商品销售、取消与退货、运费、折扣及财务调整。对 `POST`、`DOT`、`BANK CHARGES` 等非产品代码单独核算，明确销售额与净交易金额的统计口径，避免混淆。

**用途 B：客户分群与 RFM 模型**

Customer ID 缺失记录占22.77%，应单独标记而非直接删除。按客户和发票聚合，并明确取消、退货及特殊费用的处理规则，避免影响客户价值评估。

**用途 C：商品推荐模型**

保留真实商品交易，排除已确认的费用和财务调整。对礼品券、测试记录、缺失描述及特殊代码，应结合业务含义核查，不能仅凭代码格式过滤。

## 二、看似脏但不应直接删除的数据

负数量可能代表退货或取消，负单价可能对应坏账调整，零单价可能涉及样品或特殊业务。数量极值也可能是真实交易及其冲销。数据集存在34,335条完全重复记录，但相同明细不一定是重复导入，因此均应先核查再决定是否处理。

## 三、有损清洗与权衡原则

删除重复行、缺失客户 ID 记录或极端值，都可能损失有效信息。应保留原始数据，在分析副本中清洗，记录处理规则，并比较处理前后的记录数与金额变化。根据不同业务目标制定清洗口径，兼顾数据质量与信息完整性。
