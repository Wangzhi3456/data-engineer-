# Q1.2 揭示数据的真实结构

## 一、问题 1：Invoice 不只是数字

### 1.1 发票编号的结构

对全部 1,067,371 条交易明细进行检查后，发现 Invoice 并非全部由数字组成。根据发票编号前缀统计，结果如下：

| 发票编号类型 | 记录数 | 记录占比 |
|---|---:|---:|
| 数字开头或无字母前缀 | 1,047,871 | 98.1731% |
| C 开头 | 19,494 | 1.8264% |
| A 开头 | 6 | 0.0006% |
| **合计** | **1,067,371** | **100.0000%** |

其中，C 开头的记录主要与取消交易有关；A 开头的记录数量很少，需要结合具体交易内容判断其业务性质。

### 1.2 不同前缀的业务含义

**（1）C 开头：取消或冲销相关记录**

对发票前缀与数量的关系进行检查，结果如下：

| 指标 | C 开头发票 | 非 C 开头发票 |
|---|---:|---:|
| 记录数 | 19,494 | 1,047,877 |
| 负数量记录数 | 19,493 | 3,457 |
| 负数量记录占组内比例 | 99.99% | 0.33% |

C 开头发票中，99.99% 的记录具有负数量，而非 C 开头发票中这一比例仅为 0.33%。两者存在明显差异，说明 C 前缀与取消或冲销行为具有很强的关联。

不过，不能据此认为所有负数量记录都属于取消交易，也不能认为所有非 C 开头记录都是正常销售。仍需结合商品代码、描述、数量、单价及完整发票信息进行判断。

**（2）A 开头：财务调整相关记录**

数据中共有 6 条 A 开头记录。其中，5 条负单价记录具有相同的业务特征：

- Invoice 以 A 开头；
- StockCode 为 `B`；
- Description 为 `Adjust bad debt`；
- Quantity 为 1；
- Customer ID 缺失；
- Price 为负数。

例如，发票 `A506401` 的 Price 为 -53,594.36，描述为 `Adjust bad debt`。

这些证据表明，负单价记录与坏账调整有关，而非普通商品销售。由于 A 开头记录数量很少，仍需逐条检查，不能仅凭前缀确定全部记录的业务性质。

**（3）数字开头：常规发票编号**

数字开头或无字母前缀的记录占 98.1731%，是数据中的主要发票类型。但这类记录中仍存在负数量、零单价及特殊业务代码。因此，发票编号的格式不能直接作为正常销售的判断标准。

### 1.3 销售总额统计应如何处理

直接将所有明细的 `Quantity × Price` 求和，可能会混合商品销售、取消、退货、运费、折扣及财务调整，无法准确反映普通商品销售额。

因此，应根据业务目的确定统计口径：

1. **普通商品销售额：** 识别真实商品交易，明确处理取消、退货和冲销，并区分费用及财务调整。
2. **净交易金额：** 根据业务定义纳入相应的销售、退货及调整记录，保留正负金额的经济含义。
3. **财务核对：** 保留所有原始记录，包括特殊前缀记录，确保交易可以追溯。

发票前缀只能作为辅助判断依据，还需结合 StockCode、Description 和交易明细进行分类。

## 二、问题 2：StockCode 也不只是产品

### 2.1 非产品业务代码的识别

StockCode 中既包含商品代码，也包含费用、折扣、财务调整及其他特殊用途代码。根据代码格式及业务描述，当前识别出以下明确的非产品业务代码：

| StockCode | 记录数 | 描述示例 | 业务含义 |
|---|---:|---|---|
| `POST` | 2,122 | POSTAGE | 邮费 |
| `DOT` | 1,446 | DOTCOM POSTAGE | 电商配送相关费用 |
| `M` | 1,426 | Manual | 手工调整 |
| `C2` | 282 | CARRIAGE | 运输或搬运费用 |
| `D` | 177 | Discount | 折扣 |
| `S` | 104 | SAMPLES | 样品相关记录 |
| `BANK CHARGES` | 102 | Bank Charges | 银行费用 |
| `ADJUST` | 67 | Adjustment by john... | 人工调整 |
| `AMAZONFEE` | 43 | AMAZON FEE | 平台费用 |
| `CRUK` | 16 | CRUK Commission | 佣金 |
| `B` | 6 | Adjust bad debt | 坏账调整 |
| `ADJUST2` | 3 | Adjustment by Peter... | 人工调整 |
| `C3` | 1 | 描述缺失 | 特殊代码，业务含义待核实 |

以上代码合计涉及 5,795 条记录，占全量记录的 0.54%；净交易金额为 -98,264.57，绝对金额为 1,819,874.47。

绝对金额占全量绝对金额的约 8.03%，明显高于其记录占比。这说明，非产品业务记录虽然数量相对较少，但对交易金额统计有重要影响。

### 2.2 其他特殊格式代码

进一步检查发现，部分不符合普通数字或数字加字母格式的代码，实际上可能对应商品、礼品券或测试交易，不能全部认定为非产品。

典型情况包括：

| 代码或代码类型 | 描述示例 | 判断及处理建议 |
|---|---|---|
| `GIFT_0001_10`、`GIFT_0001_20`、`GIFT_0001_30` | Dotcomgiftshop Gift Voucher | 礼品券，应单独识别其业务性质 |
| `DCGS0076` | SUNJAR LED NIGHT NIGHT LIGHT | 商品候选，应结合原始记录核实 |
| `DCGS0004` | HAYNES CAMPER SHOULDER BAG | 商品候选，应结合原始记录核实 |
| `TEST001`、`TEST002` | This is a test product. | 测试标记记录，应核实是否属于测试交易 |
| 部分 `DCGS` 系列代码 | 描述缺失、零单价或负数量 | 需要进一步核查 |
| 部分 `DCGS` 系列代码 | update、ebay | 仅凭描述无法确定业务属性 |

因此，特殊格式代码只能用于发现待核查记录，不能直接作为删除标准。尤其不能将所有包含字母的代码都视为非商品。

### 2.3 特殊代码对金额统计的影响

当前分类结果显示：

| 统计口径 | 记录数 | 记录占比 | 净交易金额 | 绝对金额 |
|---|---:|---:|---:|---:|
| 全量数据 | 1,067,371 | 100.00% | 19,287,250.57 | 22,658,685.71 |
| 明确的非产品业务代码 | 5,795 | 0.54% | -98,264.57 | 1,819,874.47 |
| 全部特殊格式代码，包含商品候选 | 7,465 | 0.70% | -38,792.13 | 1,889,489.53 |

**注意：** 明确的非产品业务代码与剩余特殊代码的分类汇总目前为 5,795 条和 298 条，合计 6,093 条，与全部特殊格式代码统计的 7,465 条相差 1,372 条。两者的筛选范围或汇总口径仍需进一步核对，因此不应将这两组统计直接视为完整的同一分类体系。

对于普通商品销售额统计，应将已经确认的费用、折扣、佣金和财务调整单独核算；对于礼品券、测试记录及其他待核查代码，应根据业务性质决定是否纳入。对于财务核对，则应保留原始记录并分别统计。

## 三、问题 3：可疑的极端值

### 3.1 Quantity 的最大值和最小值

数据中的 Quantity 最大值为 80,995，最小值为 -80,995。两条记录的主要信息如下：

| 字段 | 正数量记录 | 负数量记录 |
|---|---|---|
| Invoice | `581483` | `C581484` |
| StockCode | `23843` | `23843` |
| Description | PAPER CRAFT , LITTLE BIRDIE | PAPER CRAFT , LITTLE BIRDIE |
| Quantity | 80,995 | -80,995 |
| Price | 2.08 | 2.08 |
| LineAmount | 168,469.60 | -168,469.60 |
| Customer ID | 16446 | 16446 |
| Country | United Kingdom | United Kingdom |

两条记录具有相同的商品代码、描述、单价和客户 ID，数量及金额的绝对值相等、符号相反。其中，负数量记录的发票以 C 开头。

这种对应关系更符合大额交易及其后续取消或冲销的业务特征，而不是简单的随机录入错误。

但是，仅凭现有字段无法确认两条记录之间的正式业务关联，也不能确定取消原因。因此，应保留记录并结合完整发票及业务系统记录进行核查。

### 3.2 UnitPrice 为负的记录

实际字段名为 `Price`，全量数据中共有 5 条负单价记录，具有以下共同特征：

| 检查维度 | 结果 |
|---|---|
| StockCode | 全部为 `B` |
| Description | 全部为 `Adjust bad debt` |
| Invoice 前缀 | 全部为 `A` |
| Quantity | 全部为 1 |
| Customer ID | 全部缺失 |
| Price | 全部为负数 |

这些记录与坏账调整的描述及发票编号特征一致，说明负单价可能是财务调整的表达方式，而不一定是数据错误。

如果直接删除所有负单价记录，就可能损失真实的财务信息，导致净交易金额失真。

### 3.3 极端值的处理原则

对于极端数量及负单价记录，不应仅根据数值大小或正负号进行删除，而应根据业务证据分类处理：

- **保留：** 能够由取消、退货、冲销或财务调整等业务解释的记录。
- **标记并核查：** 数量或金额异常大，但暂时缺乏充分业务证据的记录。
- **修正或排除：** 只有在确认属于错误录入、重复导入或违反业务规则，并且能够明确修正依据后，才考虑对分析副本进行处理。

原始数据应始终保留。对于不同下游任务，可以使用不同的筛选规则，但必须记录筛选条件及其对统计结果的影响。

## 四、问题 4：Customer ID 的“沉默大多数”

### 4.1 缺失比例与金额贡献

全量数据共 1,067,371 条记录，其中 243,007 条缺失 Customer ID，占 22.77%。对两个群体进行比较，结果如下：

| 指标 | Customer ID 存在 | Customer ID 缺失 |
|---|---:|---:|
| 记录数 | 824,364 | 243,007 |
| 记录占比 | 77.23% | 22.77% |
| 平均 Quantity | 12.41 | 1.54 |
| Quantity 中位数 | 5 | 1 |
| 平均 Price | 3.68 | 7.95 |
| Price 中位数 | 1.95 | 3.29 |
| 涉及国家数 | 41 | 15 |
| 净交易金额 | 16,648,292.39 | 2,638,958.18 |
| 净交易金额占全量比例 | 86.32% | 13.68% |
| 绝对金额 | 18,838,565.97 | 3,820,119.74 |
| 绝对金额占全量比例 | 83.14% | 16.86% |

缺失客户 ID 的记录占全部明细的 22.77%，但其净交易金额占全量的 13.68%，绝对金额占全量的 16.86%。

这表明，缺失客户 ID 并不意味着记录没有交易价值。直接删除这些记录，会损失一部分交易金额及交易行为信息。

同时，缺失客户 ID 群体的平均数量和数量中位数均低于完整群体，而平均单价和单价中位数更高。这说明两个群体的交易明细结构存在差异，但不能仅凭这些指标推断其购买力或消费水平。

以上金额按明细行计算，不等同于订单金额或客户终身价值。

### 4.5 对缺失客户 ID 群体的推测

Customer ID 缺失可能来自未能识别客户的交易、历史系统未记录客户信息的交易，或其他无法建立客户关联的业务情形。

现有证据显示：

- 缺失记录主要来自英国；
- 其平均数量和数量中位数低于完整群体；
- 其平均单价高于完整群体，但平均订单商品金额与中位数呈现不同方向的差异；
- 两个群体的高频商品存在明显重合。

这些现象说明，缺失 Customer ID 的记录具有独立的分析价值，但不足以确定其具体对应哪一类用户。不能直接将所有缺失记录认定为匿名消费者，也不能将其全部视为异常交易。

对于客户分群和 RFM 分析，应将其单独标记为未知客户群体，不应随意填补虚构的 Customer ID。对于整体销售统计，则应在明确交易类型和金额口径后，保留其中有效的交易记录。

## 五、总结

本次探索发现，Online Retail II 并非简单的商品销售明细集合，而是同时包含正常商品交易、取消或冲销、运费、折扣、财务调整、礼品券及其他特殊记录。

因此，数据清洗的核心不应是机械地删除负数量、负单价、零单价或特殊格式代码，而应先识别业务含义，再根据销售统计、客户分群和商品推荐等不同用途制定处理规则。

对于无法确认业务含义的记录，应保留并标记待核查；对于已经有明确业务证据的特殊记录，应采用可追溯的分类规则。这样既能减少错误统计，也能避免过度清洗造成真实业务信息的损失。
