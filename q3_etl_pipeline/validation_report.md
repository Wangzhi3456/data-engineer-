## 六、数据处理规则与业务假设

### 6.1 销售数据清洗

- 排除以 `C` 开头的取消订单。
- 排除已识别的邮费、手续费、调整项等非商品交易代码。
- 保留销售数量大于 0、单价不小于 0 的有效记录。
- 保留单价为 0 的交易，不将其直接判定为无效销售。
- 保留缺少客户 ID 的有效销售记录，但不纳入客户级特征计算。

### 6.2 RFM 特征计算

| 特征 | 计算口径 |
|---|---|
| `recency_days` | 基准日期与客户最后一次购买日期之间的天数 |
| `frequency` | 客户不同购买订单的数量 |
| `monetary` | 客户有效销售记录金额之和，未扣减退货 |
| `unique_products` | 客户购买过的不同商品编码数量 |
| `first_purchase_date` | 客户首次购买时间 |
| `last_purchase_date` | 客户最后一次购买时间 |
| `country` | 客户销售记录中出现频次最高的国家 |
| `is_one_time_buyer` | 不同购买订单数是否等于 1 |

RFM 基准日期为 **2011 年 12 月 9 日**，即原始数据中的最后一个交易日期。

### 6.3 退货匹配规则

- 根据客户 ID 和商品编码寻找候选销售记录。
- 原始销售时间必须早于退货时间。
- 优先选择时间最近且剩余数量足够的原始订单。
- 每次成功匹配后扣减原始订单的剩余可退数量。
- 单条退货不跨多个原始订单拆分匹配。
- 无法满足条件的退货保留在日志中，原始订单编号设为空值。

该策略优先保证匹配的可追溯性和数量约束，不以提高匹配率为目的强制关联交易。
