# 成本报告

## 一、成本控制方案

本项目先使用本地 Python 规则和 MiniLM 进行筛选与语义分流，再将需要上下文判断的评论交给 DeepSeek V4.1 Flash。MiniLM 在本地 CPU 运行，不产生远程 API Token 费用；评论向量与 LLM 结果分别使用 SQLite 缓存，避免重复计算和重复请求。

## 二、Q4 最近一轮 API 成功请求

程序日志显示本轮选择 20 条唯一文本，其中 2 次新 API 请求成功、12 条命中历史缓存、6 条失败。两条成功请求的 Token 数与 Yeellow 账户日志逐条匹配：

| 指标 | 数值 |
|---|---:|
| 成功 API 请求 | 2 |
| 输入 Token | 1,553 |
| 输出 Token | 577 |
| 缓存读取 Token | 640 |
| 对应实际费用 | ¥0.002264 |
| 单次成功 API 请求平均费用 | ¥0.001132 |

12 条缓存命中不代表本轮新增 API 请求，不重复计入本轮调用费用。6 条失败请求未计入上述两条成功请求的费用；是否产生额外计费，以服务商账单为准。

## 四、单条成本口径与全量估算

目前可直接核实的 Q4 成功调用平均费用为 ¥0.001132/次。该值来自 2 条成功请求的实际账单匹配，样本量很小，只能作为初步参考，不能直接视为全量平均成本。

全量 DeepSeek 抽取尚未执行，因此本报告不将全量成本写成实际支出。若未来按当前平均值粗略外推，必须另列为预测，并考虑评论长度、输入上下文、输出长度、缓存命中率及失败重试带来的波动。

## 五、预算结论

当前可核实的两条 Q4 成功请求费用为 ¥0.002264。项目采用本地模型优先、按需调用 LLM 和缓存复用的策略控制成本。全量抽取费用尚未发生，也尚未完成全量预算验证。
